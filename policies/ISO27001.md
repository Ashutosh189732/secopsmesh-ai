# ISO/IEC 27001 — Information Security Management

ISO/IEC 27001 specifies requirements for establishing, implementing,
maintaining, and continually improving an information security management
system (ISMS). Annex A lists the control objectives organizations select
from based on their risk assessment.

## A.9 — Access Control

A.9 requires that access to information and information processing
facilities is limited in accordance with business and security
requirements. A.9.4.1 specifically requires restriction of access to
information in line with the access control policy — meaning storage
resources, especially those holding production or customer data, should
default to private access with explicit, reviewed exceptions for public
access, never the reverse.

## A.12 — Operations Security

A.12.1.2 (Change Management) requires that changes to the organization and
business processes, information processing facilities, and systems that
affect information security are controlled. This directly covers
infrastructure-as-code deployments and CI/CD pipelines: a Terraform or
similar change that alters a storage account's public network access
setting should go through review and approval before merge, and should be
traceable back to the specific commit and pipeline run that applied it.
A.12.4 (Logging and Monitoring) requires event logs recording user
activities, exceptions, and security events to be produced and reviewed
regularly — the basis for connecting a deployment event to a subsequent
unauthorized access incident.

## A.16 — Information Security Incident Management

A.16.1 requires a consistent and effective approach to the management of
information security incidents, including detection, reporting, assessment,
and response, with lessons learned feeding back into the ISMS. A root cause
that cites the specific deployment, commit, or configuration change
responsible is a core input to this control.
